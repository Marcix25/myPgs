MyPGS

A shared frontend library for building consistent interfaces through pgs attributes, SCSS sources, UI components and reusable JavaScript behaviours. Layouts, spacing, colours, buttons, forms, alerts, menus, modals, dropdowns, suggestion search, slides and notifications are defined once and reused across projects.

Three attributes

Everything is composed from tokens on three attributes, instead of from a class per variant.

pgs

What the element is, its visual options and its JavaScript-only flags: pgs="flex['column' 'wrap']", pgs="header['scroll']". Several components can sit together, each with its own bracket.

pgs-data

Values passed from HTML to JavaScript, always as key[payload]: dropdownPosition[top left].

pgs-state

What it is doing right now. The library writes these at runtime: open, is-active, errorField.

Getting started

npm install mypgs
import "mypgs";
import "mypgs/style.css";

The bundle initializes the registered behaviours on load. For markup added later, by JavaScript, JSX or a fetch, initialize its container with pgs.init(container).

CSS and SCSS

Prefer the library's custom properties, such as --color-primary, --padding, --gap-elements and --border-radius, to hardcoded values:

#danger-action {
  --button-background: var(--color-error);
  --button-color: var(--color-whiteFixed);
}

Component styling composes from small mixins instead of one bundled rule, so each consumer only includes what it needs: a standard button is buttonBase + buttonContent, an icon-only one swaps in iconOnly. The hover treatment is no longer part of any component's composition: it lives under pgs="hover", which the library marks on clickable surfaces by itself, and hoverNot opts any surface out of it. Variant mixins such as strong or text only add their own declarations and must follow that base. Menus, accordions, forms and step tabs follow the same explicit-composition pattern.

JavaScript helpers

Helpers collect reusable behaviour that is not a component of its own. They are registered on pgs by the library entrypoint, and their sources live in assets/javascript/helper/:

  • pgs(root): finds and edits PGS tokens, states and options.
  • pgs.init(root): initializes components added through JavaScript, JSX or an asynchronous request.
  • pgs.formValidate: form validation, messages, custom rules and external errors.
  • pgs.scrollHorizontal: turns vertical wheel movement into horizontal scrolling while the container can still scroll, whatever the input device; also registers pgs.scrollHorizontalWithMouse, the same conversion but for a plain mouse wheel only.

Conventions

  • Prefer an existing token to a new class.
  • Use component brackets for visual options, pgs-data for JavaScript configuration, and custom properties for adjustable styling.
  • Keep runtime state in pgs-state, never in parallel classes.
  • Reuse the custom properties, such as --color-primary, --gap-elements and --border-radius, instead of hardcoding values.
  • Keep project-specific work outside the library.
