MyPGS

A shared frontend library for building consistent interfaces through pgs attributes, SCSS sources, UI components and reusable JavaScript behaviors. Layouts, spacing, colors, buttons, forms, alerts, menus, modals, dropdowns, suggestion search, slides and notifications are defined once and reused across projects.

Three attributes

Everything is composed from tokens on three attributes, instead of from a class per variant.

pgs

What the element is, its visual options and its JavaScript-only flags: pgs="flex['column' 'wrap']", pgs="header['headerScroll']". Several components can sit together, each with its own bracket.

pgs-data

Values passed from HTML to JavaScript, always as key[payload]: dropdownPosition[top left].

pgs-state

What it is doing right now. The library writes these at runtime: open, active, errorField.

Getting started

Terminal 
npm install mypgs
JavaScript 
import "mypgs";
import "mypgs/style.css";

The bundle initializes the registered behaviors on load. For markup added later, by JavaScript, JSX or a fetch, initialize its container with pgs.helper.init(container).

CSS and SCSS

Prefer the library's custom properties, such as --color-primary, --padding-elements, --gap-elements and --borderRadius-elements, to hardcoded values:

CSS 
#danger-action {
    --button-background: var(--color-error);
    --button-color: var(--color-whiteFixed);
}

Component styling composes from small mixins instead of one bundled rule, so each consumer only includes what it needs: a standard button is buttonBase, an icon-only one adds buttonIconOnly. Buttons and link cards and boxes carry a plain CSS hover of their own. Variant mixins such as buttonTransparent or buttonText only add their own declarations and must follow that base. Menus, accordions, forms and step tabs follow the same explicit-composition pattern.

JavaScript helpers

Helpers collect reusable behavior that is not a component of its own. They are registered on pgs.helper by the library entrypoint, and their sources live in assets/javascript/helper/:

  • pgs(root): finds and edits PGS tokens, states and options.
  • pgs.helper.init(root): initializes components added through JavaScript, JSX or an asynchronous request.
  • pgs.helper.formValidate: form validation, messages, custom rules and external errors.
  • pgs.helper.warn, dispatch, uniqueId, escapeHtml and the other small helpers the library is built on.

Conventions

  • Prefer an existing token to a new class.
  • Use component brackets for visual options, pgs-data for JavaScript configuration, and custom properties for adjustable styling.
  • Keep runtime state in pgs-state, never in parallel classes.
  • Reuse the custom properties, such as --color-primary, --gap-elements and --borderRadius-elements, instead of hardcoding values.
  • Keep project-specific work outside the library.

Only what a project uses

Every component is in the bundle by default.

A project can list the ones it uses in a mypgs.config.json next to its build config.

The example lists every name of assets/modules.json: copy it and remove what the project does not use.

mypgs.config.json 
{
    "include": [
        "accordion", "alerts", "badges", "breadcrumb", "button",
        "buttonGroup", "card", "dropdown", "form", "formAddon",
        "formControls", "formValidate", "icon", "listbox", "logo",
        "menu", "modal", "notification", "pagination", "pageNav",
        "rating", "search", "slides", "steps", "stepTabs",
        "summary", "table", "tabs", "toast", "pageShell",
        "header", "navSmart", "footer"
    ]
}
  • Every part not listed is left out, a component added to the library later too, until the project lists it.
  • What a listed part needs is added, with a message: a modal brings its button and icon, a toast its alerts.
  • An unknown name stops the build.
  • Without the file, or without include in it, every part is in.
  • The base, the patterns (color, border, typography, general) and the layout utilities (section, flex, grid, flexGrid, breakpoints, utilities, spacing, size) are always in.

mypgs/build reads the file and gives the build what it needs. It works on the sources, the SCSS and import "mypgs", not on the prebuilt style.css.

webpack.config.js 
const modules = require("mypgs/build").pgsModules();

module.exports = [
    {
        // the JavaScript bundle: a module left out becomes an empty one
        entry: "./assets/javascript/index.js",
        resolve: { alias: modules.alias },
    },
    {
        // the SCSS bundle: sets $pgs-exclude before the library is loaded
        entry: "./assets/scss/index.scss",
        module: {
            rules: [{
                test: /\.scss$/,
                use: [MiniCssExtractPlugin.loader, "css-loader", {
                    loader: "sass-loader",
                    options: { additionalData: modules.sass },
                }],
            }],
        },
    },
];
vite.config.js 
import { defineConfig } from "vite";
import { pgsModules } from "mypgs/build";

const modules = pgsModules();

export default defineConfig({
    plugins: [modules.vite()],
    css: {
        preprocessorOptions: {
            scss: { additionalData: modules.sass },
        },
    },
});

A module left out is missing from pgs: pgs.slides is undefined, and without formValidate there is no pgs.helper.formValidate.
